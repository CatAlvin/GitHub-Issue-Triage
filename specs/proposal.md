# GitHub Issue 分诊助手

## 目标与背景

面向开源项目维护者，将 Issue 快照整理为时间窗口摘要、可解释风险列表和带来源的贡献流程回答，减少逐条浏览的工作。项目作者负责需求、数据接入、业务逻辑、接口和测试。

## 范围

- GT-01：读取本地 Issue 快照，提供显式 GitHub 拉取命令，过滤 Pull Request 并校验字段。
- GT-02：按创建时间生成最近 1 至 90 天摘要；超过 8 条采用分块归并；最多处理最新 40 条并提示截断。
- GT-03：独立输出三条风险规则的证据，不合并为无法解释的分数。
- GT-04：从贡献指南检索前三个片段；最高分低于 0.05 或没有内容词重叠时拒答。
- GT-05：提供 CLI、Slack Socket Mode、stdio MCP 和 HTTP MCP，共用业务函数。
- GT-06：默认离线；真实模型须设置 APP_MODE=live 和供应商密钥；配置只读取项目目录。
- GT-07：提供健康与就绪检查、可选 Bearer 令牌、可重现演示及自动验证。

本期不包括自动改标签、提交评论、结构化任务提取、多 Agent 路由、向量数据库或多租户权限。

## 成功标准

| 编号 | 可验证条件 |
| --- | --- |
| GT-AC01 | 内置 25 条记录全部通过字段校验；错误类型、负数计数及非法日期被拒绝 |
| GT-AC02 | 快照时钟下摘要非空；仅包含时间窗口内最新 40 条；未来记录不进入窗口 |
| GT-AC03 | 三条规则均有正反例及时间边界测试；未来时间不触发快速升级 |
| GT-AC04 | 相关问题带来源；无关问题与空知识库拒答 |
| GT-AC05 | HTTP 健康/就绪、令牌校验、MCP 列举与调用通过；离线演示无模型网络请求 |
| GT-AC06 | specs 中的 HTTP 契约与运行时 OpenAPI 一致，MCP 工具名及输入 Schema 一致 |

## 技术约束

Python 3.12，FastAPI，官方 MCP Python SDK，TF-IDF 本地检索。Docker 镜像构建不抓取业务数据。性能与真实模型质量在独立数据和运行条件下测量，本规格不把规则测试作为业务准确率。

## 前端工作台

通过浏览器完成数据概览、记录筛选、任务或风险跟进、知识问答、来源阅读及简报导出。所有统计来自当前项目数据；交互与验收标准见 [workbench.md](workbench.md)。
